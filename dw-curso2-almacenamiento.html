01 · La forma de los datos

Estructurados, semiestructurados y no estructurados

Estructurados

Filas y columnas con un esquema fijo.

Tablas de una base de datos, hojas de cálculo, transacciones.

Semiestructurados

Tienen etiquetas o claves, pero un esquema flexible.

JSON, XML, registros (logs).

No estructurados

Sin un modelo predefinido.

Imágenes, video, audio, PDF, texto libre, correos.

Pista de examen: «datos en sus formatos nativos» o «estructurados y no estructurados» → pensá en lake / lakehouse.

02 · Formas de almacenar

¿Dónde se guardan los datos?

OpciónQué esUsala cuando…
Base de datosDatos estructurados para operaciones y transacciones del día a día.Necesitás una fuente estructurada que maneje grandes volúmenes.
Sistema de registroFuente oficial y autorizada de un dato crítico (ej.: clientes).Los datos son muy importantes y hay que protegerlos de accesos no autorizados.
Almacén de datosRepositorio central de datos estructurados de muchas fuentes, para análisis.Datos muy estructurados que usan varios departamentos.
Data martSubconjunto temático de un almacén más grande (ventas, marketing…).Un área necesita solo sus datos, rápido.
Data lakeRepositorio de datos crudos en su formato nativo, de cualquier tipo.Querés guardar todo sin decidir aún cómo se usará.
Data lakehouseAlmacén de datos + data lake en una sola arquitectura.Mezcla de estructurados y no estructurados con informes rápidos.

05 · Datos anidados y repetidos

STRUCT, ARRAY y modos

STRUCT / RECORD

Grupo de campos dentro de una columna.

cliente: STRUCT<nombre, ciudad>

ARRAY

Lista de valores del mismo tipo en una sola fila.

productos: ARRAY<STRUCT<nombre, descripcion, precio>>

Modos

NULLABLE admite nulos (por defecto)
REQUIRED obligatorio
REPEATED es un array

-- un pedido con su lista de productos
SELECT pedido_id, p.nombre, p.precio
FROM tienda.pedidos, UNNEST(productos) AS p;
Anidar y repetir es una forma de desnormalizar: los datos relacionados viajan juntos y se evitan JOINs costosos.

Clave primaria: identifica de forma única cada fila (no se repite, no es nula).

Clave externa: columna que referencia la clave primaria de otra tabla → permite relacionar y unir tablas.

SELECT c.nombre, v.producto
FROM tienda.clientes AS c
JOIN tienda.compras AS v
  ON v.id_cliente = c.id_cliente;

07 · Modelado

Normalización vs desnormalización

NormalizaciónDesnormalización
IdeaDividir en tablas relacionadas por claves; cada dato en un solo lugar.Combinar datos; agregar columnas duplicadas en cada tabla (o anidarlas).
ObjetivoEvitar duplicados e inconsistencias; facilitar actualizaciones.Lecturas y consultas rápidas, sin JOINs.
CostoConsultas con más JOINs.Más espacio; actualizar en varios lugares.
Uso típicoSistemas transaccionales (OLTP).Almacenes y análisis; detectar fraude rápido en un gran flujo.

09 · Gobierno y administración

Gobierno de datos

Marco de políticas, normas, roles y responsabilidades para que los datos sean confiables, seguros y utilizables en toda la organización.

Administración y propiedad

Quién es responsable de cada conjunto de datos.

Datos maestros (MDM)

10 · Catálogo de datos

Encontrar y entender los datos

Un catálogo de datos es un inventario buscable de los activos de datos con sus metadatos (datos sobre los datos). Da una visión completa para descubrir, comprender y usar los activos, y ayuda a seguir su origen y transformación.

Knowledge Catalog / Dataplex (Google Cloud): descubrimiento, metadatos y gobierno centralizados de datos repartidos en lakes, almacenes y marts.

Para encontrar y comprender activos hacen falta las herramientas adecuadas + entender el objetivo comercial.

13 · SQL básico

Las cinco cláusulas

SELECT ciudad, COUNT(*) AS clientes  -- columnas
FROM tienda.clientes                 -- tabla
WHERE pais = 'UY'                    -- filtra filas
GROUP BY ciudad                      -- agrupa
ORDER BY clientes DESC               -- ordena
LIMIT 10;
  • SELECT inicia la consulta y elige columnas.
  • FROM de qué tabla.
  • WHERE solo las filas que cumplen una condición.
  • GROUP BY agrupa para agregar (COUNT, SUM, AVG).
  • ORDER BY ordena el resultado.

Cada herramienta puede usar un dialecto de SQL distinto (BigQuery usa GoogleSQL). BigQuery también permite búsquedas basadas en texto, por ejemplo dentro de JSON.

14 · Particionamiento

Dividir para consultar menos

Horizontal

Por filas: mismas columnas, distintas filas (ej.: por año), repartidas en múltiples servidores.

Vertical

Por columnas: columnas de uso frecuente separadas de las demás.

Funcional

Según el uso de los datos dentro del sistema (ventas, inventario…).

En BigQuery y buenas prácticas
  • Por columna de fecha/hora, por tiempo de ingesta o por rango de enteros.
  • Repartir en varios servidores evita un punto único de fallo.
  • Reducción: consultar solo las particiones necesarias.
  • Tráfico desigual → volver a equilibrar particiones.
CREATE TABLE ventas.pedidos
PARTITION BY DATE(fecha) AS
SELECT * FROM crudo.pedidos;

SELECT SUM(monto) FROM ventas.pedidos
WHERE DATE(fecha) = '2026-10-01';  -- lee 1 partición

15 · Procesamiento y aprendizaje automático

Dataproc y AA en BigQuery

Dataproc

Servicio administrado para Apache Spark y Hadoop (código abierto): procesamiento por lotes, consultas, transmisión y AA sin administrar clústeres a mano.

SDK (kit de desarrollo de software): biblioteca de código que funciona como interfaz para acceder a datos o servicios externos.

BigQuery ML

Crear y usar modelos de AA con SQL, donde ya están los datos.

OPTIONS(model_type='linear_reg') AS
SELECT precio, promo, ventas AS label
FROM tienda.historico;
