02 · Cómo está armada

Frontend, backend y almacenamiento

Componentes del backend

AplicaciónServicioEntorno de ejecuciónAlmacenamientoInfraestructuraAdministraciónSeguridad

  • Seguridad: protege los datos y mantiene su privacidad.
  • Entorno de ejecución (runtime): ejecuta los servicios de forma eficiente y sin demoras.
  • Infraestructura: hardware real (servidores, red); administración: coordina los recursos.

El frontend es lo que usa el cliente: navegador, app, interfaz.

Tipos de almacenamiento en la nube
  • Archivos: jerarquía de carpetas; simple y fácil de entender.
  • Bloques: datos divididos en bloques de tamaño fijo; baja latencia (discos de VM, bases de datos).
  • Objetos: cada objeto con sus datos, metadatos e ID, en buckets; escala masiva, ideal para no estructurados.

ModeloEl proveedor te da…Vos administrás…Pista típica

04 · Modelos de implementación

¿Dónde vive la nube?

Pública

Recursos del proveedor, accesibles por Internet y compartidos entre varios usuarios y organizaciones.

Escalar sin comprar hardware: ideal para una startup con poca TI.

Privada

Infraestructura dedicada a una sola organización (propia o de un proveedor).

Más control y aislamiento.

Híbrida

Combina infraestructura local/privada + nube pública.

Ej.: una normativa exige guardar ciertos datos de forma local.

Multinube

Usa servicios de varios proveedores de nube pública.

Evita depender de uno solo; elige lo mejor de cada uno.

05 · Beneficios

¿Por qué la nube?

Escalabilidad

Aumentar o reducir recursos según lo que se necesite.

Ajuste de escala automático

Los recursos se ajustan solos a la demanda (picos y bajas).

Aprovisionamiento dinámico

Asigna recursos en el momento ante demanda impredecible; pagás solo lo usado.

Ahorro de costos

Pago por uso: transacciones, almacenamiento y transferencia de datos que realmente usás.

Seguridad

Controles del proveedor + cifrado + permisos administrados.

Recuperación ante desastres

Copias redundantes: los datos siguen protegidos incluso en una emergencia.

06 · Costos y optimización

¿Qué se paga en la nube?

Almacenamiento

Cantidad de datos guardados y por cuánto tiempo.

Procesamiento

Datos procesados por las consultas y potencia de cómputo usada.

Uso de red

Datos que se leen o trasladan entre buckets de almacenamiento o regiones.

Cómo optimizar
  • Borrar o archivar lo que no se usa; elegir la clase de almacenamiento adecuada.
  • Consultar solo columnas y particiones necesarias (evitar SELECT *).
  • Presupuestos, alertas y monitoreo del gasto.
Efectos

Menos recursos desperdiciados → menor gasto y reducción de la emisión de carbono.

Dataset muy grande: administrar el almacenamiento para no pagar de más.

07 · Almacenes de datos en la nube

Un lugar central para analizar

Un almacén de datos integra datos de muchas fuentes en un repositorio central optimizado para consultas, informes y análisis, separado de los sistemas operativos del día a día.

Analítica en tiempo real

Paneles con datos actuales (ej.: lecturas de sensores).

Informes personalizados

Análisis de datos históricos sin cargar los sistemas operativos.

Integración

Une fuentes diversas; escala sin administrar servidores.

SQL + IA/AA

Consultas SQL y modelos de aprendizaje automático sobre los mismos datos.

Ejemplo de beneficio: una universidad obtiene información sobre la evaluación y la eficacia de sus cursos y contenidos.

08 · BigQuery

BigQuery: almacenar y analizar

Almacén de datos de Google Cloud, sin servidor y totalmente administrado: guardás los datos y los analizás con SQL, sin gestionar infraestructura.

Proyecto · contenedor de recursos, facturación y permisos
Conjunto de datos (dataset) · agrupa tablas
Tabla · filas y columnas con un esquema
Nombre completo de una tabla
SELECT nombre, ciudad
FROM `mi-proyecto.tienda.clientes`
WHERE ciudad = 'Montevideo';

Caso típico: analizar datos de clientes para encontrar tendencias → BigQuery.

11 · Retención y control de versiones

Cuánto guardar y cómo volver atrás

Retención de datos

Política que fija cuánto tiempo se conserva cada tipo de dato según su utilidad y la normativa.

Al vencer: archivar o destruir.

Guardar «todo para siempre» aumenta costos y riesgos.

Control de versiones

Registra cada cambio de los datos para saber quién cambió qué y cuándo.

  • Respalda el control de calidad.
  • Ayuda a abordar el cumplimiento.
  • Permite revertir a una versión anterior.

12 · Seguridad, privacidad y acceso

Proteger los datos (y a las personas)

PII

Información de identificación personal: nombre, dirección, fecha de nacimiento, datos financieros.

RGPD (GDPR)

Reglamento General de Protección de Datos de la UE: aplica a datos personales de ciudadanos de la UE.

Acceso por roles

RBAC: los permisos se asignan a roles, no persona por persona; escala bien al crecer.

Mínimo privilegio

Grupo de seguridad por rol con solo los permisos necesarios.

Seguridad = impedir accesos no autorizados. Privacidad = usar los datos personales de forma adecuada y legal.

14 · Herramientas de Google Cloud

El kit básico

BigQuery

Almacén de datos: almacenar y analizar con SQL.

Cloud Storage

Almacenamiento de objetos: aloja en un solo lugar datos de servidores remotos (bases de apps, estadísticas, herramientas).

Dataproc

Spark y Hadoop administrados (código abierto): lotes, consultas, transmisión y AA.

Looker

Plataforma de BI: organizar datos, crear flujos de trabajo y apps, informes y visualizaciones en una sola herramienta.

Looker Studio

Paneles e informes interactivos para visualizar y compartir datos.

Recordá

Guardar → Cloud Storage / BigQuery · procesar → Dataproc · mostrar → Looker.
