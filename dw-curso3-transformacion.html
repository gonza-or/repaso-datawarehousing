02 · Técnicas de transformación

¿Qué le hacemos a los datos?

Limpieza

Corregir errores, faltantes y valores inválidos.

Estandarización

Formato uniforme: fechas, unidades, mayúsculas.

Conversión

Cambiar el tipo o formato para mejorar la compatibilidad.

Deduplicación

Quitar registros idénticos o parcialmente idénticos.

Agregación y filtrado

Resumir por grupo (totales, promedios) y quedarse con lo relevante.

Derivación y enriquecimiento

Crear campos nuevos; sumar datos de otras fuentes.

Anonimización / enmascaramiento: ocultar o reemplazar la PII (ej.: ****1234) antes de compartir o analizar.

03 · Cómo se transforma

Manual, automática o con consultas

ManualAutomática
QuiénUna persona, paso a pasoHerramientas y canalizaciones programadas
CuándoPocos datos, casos puntualesGrandes volúmenes, tareas repetidas
RiesgoLenta y propensa a erroresRequiere diseño y monitoreo
Transformación a través de consultas (SQL)
CREATE OR REPLACE TABLE limpio.ventas AS
SELECT TRIM(UPPER(pais)) AS pais,
       SAFE_CAST(monto AS FLOAT64) AS monto,
       DATE(fecha) AS fecha
FROM crudo.ventas
WHERE monto IS NOT NULL;

Con datasets grandes, el recurso que suele complicar es el almacenamiento.

Extracción, transformación y carga

FuentesBases, APIs, archivos, apps
→
EExtracciónSacar los datos y trasladarlos a un área intermedia temporal (staging).
→
TTransformaciónLimpiar, estandarizar, unir, agregar.

05 · Orden de la canalización

ETL vs ELT

ETL · extraer → transformar → cargarELT · extraer → cargar → transformar
Dónde se transformaEn un área o herramienta intermedia, antes de cargarDentro del almacén en la nube, después de cargar
Qué se cargaSolo datos ya limpiosDatos crudos; se transforman luego
FlexibilidadMenor: reglas definidas de antemanoMayor: transformar según se necesite y volver a hacerlo
Elegilo cuando…Hay que limpiar o anonimizar antes de guardar; destino con poca capacidad; reglas establesGrandes volúmenes y se aprovecha la nube para el almacenamiento y cómputo (ej.: BigQuery)

06 · Transferencia de datos

Por lotes vs transmisión

Diseñar la transferencia = decidir qué técnica lleva los datos de las fuentes al área intermedia. Factor clave: ¿los datos son urgentes?
Por lotes
  • Se mueven en intervalos programados (cada hora, cada noche).
  • Costos más bajos.
  • Datos no críticos o históricos.
Transmisión
  • Se procesan apenas están disponibles, de forma continua.
  • Más costosa y compleja.
  • Datos urgentes: alertas, paneles en vivo.

08 · Perfilamiento y limpieza

Conocer los datos antes de usarlos

Perfilamiento: examinar estructura, contenido y calidad (conteos, nulos, valores distintos, mínimos y máximos).

Problemas a corregir
  • Errores de entrada: tipográficos, valores mal escritos.
  • Duplicados e incompletos (faltantes, NULL).
  • Inconsistentes (formatos) y atípicos.

Importa porque los errores afectan la integridad de los datos y las conclusiones.

-- perfil rápido de una tabla
SELECT COUNT(*)              AS filas,
       COUNT(email)          AS con_email,
       COUNT(DISTINCT email) AS emails_unicos,
       MIN(monto) AS minimo,
       MAX(monto) AS maximo
FROM crudo.clientes;

09 · Validación de datos

¿Los datos cumplen las reglas?

ValidaciónComprueba que…
De tipoEl valor es del tipo esperado (una fecha es fecha).
De formatoSigue un patrón (email, teléfono).
De rangoEstá dentro de límites (edad 0–120).
De duplicadosHay unicidad: la clave no se repite.
De nulos / completitudLos campos obligatorios están presentes.
Diccionario de datos

Documento que describe cada campo: nombre, definición, tipo, formato, valores permitidos y fuente.

Es la referencia para validar y para que todos interpreten igual los datos.

SELECT id_cliente, COUNT(*) AS n
FROM limpio.clientes
GROUP BY id_cliente
HAVING COUNT(*) > 1;  -- unicidad

Carga completa vs incremental

Carga completaCarga incremental
Qué haceReemplaza todo el destino en cada ejecuciónAgrega solo registros nuevos o modificados desde la última carga
VentajaSimple; ideal para la carga inicialRápida y barata con volúmenes grandes

Plan de transformación

1. Objetivo de negocio → 2. fuentes y perfilamiento → 3. asignación origen-destino → 4. reglas de transformación y validación → 5. ETL/ELT y lotes/transmisión → 6. probar, documentar y monitorear.

11 · Agregación de datos

Resumir para ver tendencias

Agregación: combinar muchos registros en valores resumidos por grupo para encontrar tendencias (ej.: hábitos de compra).

Cuidado con los NULL
  • COUNT(*) cuenta todas las filas.
  • COUNT(col), SUM, AVG ignoran los NULL.
  • Decidir: completar (IFNULL / COALESCE), excluir o marcar.
-- total de reproducciones por canción por día
SELECT cancion_id,
       DATE(ts)  AS dia,
       COUNT(*)  AS reproducciones
FROM musica.escuchas
GROUP BY cancion_id, dia
ORDER BY dia, reproducciones DESC;

12 · Datos duplicados

Detectar y quitar duplicados

Un dato duplicado es una copia exacta (o casi) de otro registro. Infla conteos y sumas.
Filas idénticas
SELECT DISTINCT *
FROM crudo.clientes;
Una fila por clave (la más reciente)
SELECT *
FROM crudo.clientes
QUALIFY ROW_NUMBER() OVER (
  PARTITION BY email
  ORDER BY actualizado DESC) = 1;

13 · Uniones (JOIN)

Combinar tablas

INNER JOIN

Solo filas que coinciden en ambas tablas (unión interna).

LEFT JOIN

Todas las de A + coincidencias de B; NULL si no hay.

RIGHT JOIN

Todas las de B + coincidencias de A.

FULL OUTER JOIN

Todas las filas de ambas, coincidan o no.

SELECT c.nombre, p.total
FROM tienda.clientes AS c
INNER JOIN tienda.pedidos AS p ON p.id_cliente = c.id_cliente;

14 · Datos derivados y RFM

Crear información nueva

Datos derivados: valores calculados a partir de otros (edad desde la fecha de nacimiento, margen, totales).

Problema a considerar: no siempre son tan exactos como los datos originales (redondeos, supuestos, errores que se arrastran).
R

Recencia: ¿hace cuánto compró?

F

Frecuencia: ¿cuántas veces?

M

Monetario: ¿cuánto gastó?

-- análisis RFM: datos derivados por cliente
SELECT cliente_id,
  DATE_DIFF(CURRENT_DATE(), MAX(fecha), DAY)
                AS recencia,
  COUNT(*)      AS frecuencia,
  SUM(monto)    AS monetario
FROM ventas.pedidos
GROUP BY cliente_id;
